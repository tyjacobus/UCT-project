Quantum vs. Randomized Computation

In this chapter we will see how randomized and quantum computation can be described in almost the exact same way with vectors and matrices. The only real difference between them is that quantum amplitudes can be negative. We also show how we can view randomized and quantum computation as a graph where the results is a sum across the paths of that graph.

Randomized computation is linear algebra

Think of a randomized algorithm that uses $m$ bits of memory. During computation, the state is a probability distribution over $\{0,1\}^m$, which is a vector $p\in\R^{2^m}$ with $p_z\ge0$ and $\sum_z p_z = 1$. Each step changes the distribution linearly: if the step moves from memory contents $z$ to $z'$ with probability $M_{z',z}$, then the new distribution is $Mp$.

Definition (Stochastic matrix)

A real matrix $M$ is stochastic if all its entries are nonnegative and each column sums to $1$. These are the matrices that map all probability vector into another probability vector. We can see the most basic example of this with the a matrix representation of a coin flip $$F = \begin{pmatrix}\tfrac12&\tfrac12\\[2pt]\tfrac12&\tfrac12\end{pmatrix},$$ Note that classical gates are also stochastic.

Side by side, the two models look almost the same:

We can start to see how there is a difference in the models with the example below.

Example (Flip a coin twice vs. apply $H$ twice)
We have seen that $H$ looks almost exactly like a fair coin flip in classical probability but this will show us a difference.

Randomized. Start with just the bit $0$ so $p = (1,0)^T$.
$Fp = (\tfrac12,\tfrac12)^T$, and $F(Fp) = (\tfrac12,\tfrac12)^T$.
Applying F twice does nothing.

Quantum. Start with $\ket0$.
$H\ket0 = \ket+$, which looks like a fair coin if we measure it.
But $H\ket+ = \ket 0$ (see example): the outcome is just $0$. We've somehow lost any randomness that existed.

Sum over paths

As we've talked about, we can look at computation that applies these matrices $U_1$, then $U_2$, ..., $U_T$, to some basis state $\ket x$ as a tree. At each step, it branches from the current state to $(U_i)_{z_i, y}\ne0$, The results are a sum over paths from the root to some set of the leaves. Note that this process is just matrix multiplication.

Lemma (Sum-over-Paths Lemma)

Let $U_1,\dots,U_T$ be $2^m\times2^m$ matrices and $x,y\in\{0,1\}^m$. Then $$\big(U_T\cdots U_1\big)_{y,x} \;=\; \sum_{z_1,\dots,z_{T-1}\in\{0,1\}^m}\;\prod_{t=1}^{T}\,(U_t)_{z_t,\,z_{t-1}},$$ where $z_0 = x$ and $z_T = y$.

Proof. We can prove this using induction on $T$. Note that $z_0 = x$ and $z_T = y$.

For the base case where $T=1$, the sum has only one term and the product only has one factor: $$\sum_{\text{(nothing)}}\;\prod_{t=1}^{1}(U_t)_{z_t,\,z_{t-1}} = (U_1)_{z_1,\,z_0} = (U_1)_{y,x}.$$

Step, $T>1$. By the definition of matrix multiplication, we have $$(U_T\cdots U_1)_{y,x} = \sum_{z_{T-1}\in\{0,1\}^m}(U_T)_{y,\,z_{T-1}}\,\big(U_{T-1}\cdots U_1\big)_{z_{T-1},\,x}.$$ The second factor is a product of $T-1$ matrices, so we can apply the induction hypothesis: $$\big(U_{T-1}\cdots U_1\big)_{z_{T-1},\,x} = \sum_{z_1,\dots,z_{T-2}}\;\prod_{t=1}^{T-1}(U_t)_{z_t,\,z_{t-1}}.$$ This gives us: $$(U_T\cdots U_1)_{y,x} = \sum_{z_{T-1}}(U_T)_{y,\,z_{T-1}}\sum_{z_1,\dots,z_{T-2}}\;\prod_{t=1}^{T-1}(U_t)_{z_t,\,z_{t-1}}.$$ Note that $(U_T)_{y,\,z_{T-1}}$ doesn't depend on $z_1,\dots,z_{T-2}$ so we can move it inside the sum and combine the two sums. $$(U_T\cdots U_1)_{y,x} = \sum_{z_1,\dots,z_{T-1}}(U_T)_{z_T,\,z_{T-1}}\prod_{t=1}^{T-1}(U_t)_{z_t,\,z_{t-1}} = \sum_{z_1,\dots,z_{T-1}}\;\prod_{t=1}^{T}(U_t)_{z_t,\,z_{t-1}}.$$ ∎

The Sum-over-Paths Lemma works for matrices that represent randomized computation and matrices that represent quantum computation. The only difference in what the weights that are being added up are:

Example (The paths of $HH\ket0$)
$$\amp{0}{HH}{0} = \tfrac12 + \tfrac12 = 1,\qquad \amp{1}{HH}{0} = \tfrac12 - \tfrac12 = 0 .$$ This tree and the tree that is created by two coin flips are the same except for the sign on one edge, and that sign is what makes the paths to $\ket1$ cancel.

Remark (How quantum algorithms work)

Despite quantum algorithms creating exponential paths in these tree representation, unlike the trees that come from randomized algorithm, the signs at the leaves of the quantum trees allow incrorect answers to cancel out. This representation also shows how we could naively simulate a quantum computer on a TM by just adding up the path weight. This hints to an upper bound for $\mathsf{BQP}$ being $\mathsf{PSPACE}$.

Interference needs paths that end in the same place

Note that this cancelation doesn't always occur. We can see an example below showing us exactly when results cancel.

Example (“Which-path” information stops interference)

Take the circuit on qubit 1 from the coin-versus-Hadamard example, and add a CNOT between the two $H$ gates that copies qubit 1 into a qubit 2.

$\ket{\psi_1} = \tfrac1{\sqrt2}(\ket{00}+\ket{10})$, and $\ket{\psi_2} = \tfrac1{\sqrt2}(\ket{00}+\ket{11})$ (a Bell state). Applying $H$ to qubit 1: $$\ket{\psi_3} = \tfrac12\big(\ket{00} + \ket{10}\big) + \tfrac12\big(\ket{01} - \ket{11}\big).$$ $\Pr[\text{qubit 1 reads }1] = \tfrac14+\tfrac14 = \tfrac12$.

The leaf values explain why this cancelation didn't occur in this example. The paths that lead to “qubit 1 $=1$” still have weights $+\tfrac12$ and $-\tfrac12$, but in this case they end up in different basis states so these two paths never cancel.

Remark (The interference principle)

Two paths will cancel if and only if they they end in the same basis state.

This is why we will talk about uncomputing scratch work (Bennett’s Uncomputation Lemma).

Summary

  • Randomized computation uses nonnegative weights and quantum computation uses signed weights. Everything else is the same.
  • An amplitude is a sum of path weights. Probabilities just add up but amplitudes can cancel.
  • Paths only cancel if they end at the same basis state.
